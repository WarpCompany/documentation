<Note>
  **Roadmap.** The ZK Validator Network is a design proposal and is not yet available. This page describes planned behavior, which may change.
</Note>

The ZK Validator Network is a planned network of independent validators that would check zero-knowledge proofs and return a deterministic valid or invalid result, without learning the private inputs behind them. Today, proofs are verified on-chain by your own verifier contract or through the [hosted verification API](/zkproofs/introduction#verify-with-the-warp-api).

## Planned role

Proofs would be generated off-chain by users, bots or backends. The network would verify them against the circuit's known verifier parameters, and downstream contracts or services would act only on a valid result.

The network would:

- Validate proofs against deployed circuits or verification keys
- Reject malformed or invalid proofs
- Produce a yes/no result that other systems can rely on

It would not execute user logic, inspect private inputs or make subjective decisions.

## Why a separate layer

Verifying every proof on a base-layer chain is costly at scale. A dedicated network is intended to:

- Keep verification cost predictable
- Support more proving systems over time
- Decentralize verification without trusted intermediaries
- Anchor results to a base layer where settlement needs it
